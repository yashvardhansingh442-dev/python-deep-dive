# Roadmap

The full learning path for this repo: what is covered, in what order, how deep, and what is still planned.

> **Source of truth:** `topics.yml` at the repo root. The progress tables between the `<!-- PROGRESS:START -->` and `<!-- PROGRESS:END -->` markers are generated by `make progress`. Do not edit them by hand. Everything else in this file is written by hand.

---

## 1. How to read this roadmap

### Status key

| Symbol | Meaning |
|---|---|
| ✅ | Done: notes, examples, exercises, solutions and tests all merged |
| 🚧 | In progress: partially written, may change |
| 📝 | Planned: scoped, not started |
| 💡 | Idea: not yet scoped, open for discussion |

### Difficulty key

| Tag | Level | You should already be able to |
|---|---|---|
| 🟢 | Foundation | Write and run a basic script |
| 🟡 | Intermediate | Build small programs with functions and classes |
| 🔴 | Advanced | Read other people's library code comfortably |
| ⚫ | Expert | Read CPython source and reason about runtime behavior |

### Depth tiers inside every module

Each topic in a module is tagged with one of three tiers so you can choose how far to go.

| Tier | Goal | Output |
|---|---|---|
| **Core** | Use it correctly in real code | Notes + examples + exercises |
| **Deep** | Explain *why* it behaves that way | `deep-dive.md` with `dis`, source references, diagrams |
| **Mastery** | Build it yourself or debug it under pressure | A from-scratch implementation in `src/pydeep/` or a project |

## 4. Detailed curriculum

Each module follows the same shape: **goal, prerequisites, topics (by tier), exercises, deliverable, self-check.**

---

### Module 00: Setup and Tooling 🟢

**Goal:** A reproducible, professional environment before writing any real code.
**Prerequisites:** None. **Time:** about 4 h.

**Core**
- [ ] Installing Python (system vs `pyenv` vs `uv`), choosing a version
- [ ] Virtual environments: `venv`, activation, why they exist
- [ ] `pip`, `requirements.txt` vs `pyproject.toml`
- [ ] Running scripts: `python file.py`, `python -m module`, `if __name__ == "__main__"`
- [ ] Editor setup: VS Code or PyCharm, interpreter selection, debugger basics
- [ ] Git workflow for this repo: branches, commits, pull requests

**Deep**
- [ ] How Python finds modules: `sys.path`, `PYTHONPATH`, editable installs
- [ ] What a virtual environment actually changes on disk

**Exercises:** Create a venv, install the repo with `make install`, run the test suite, break a test on purpose and fix it.
**Deliverable:** A working local environment where `make check` passes.
**Self-check:** Can you explain what `pip install -e .` does differently from `pip install .`?

---

### Module 01: Core Language 🟢

**Goal:** Fluent, idiomatic Python for everyday programs.
**Prerequisites:** Module 00. **Time:** about 14 h.

**Core**
- [ ] Variables, names and assignment; dynamic typing
- [ ] Numbers: `int`, `float`, `complex`, `Decimal`, `Fraction`; float pitfalls
- [ ] Strings: slicing, methods, f-strings, formatting mini-language, encodings
- [ ] Booleans, truthiness, `and` / `or` short-circuiting
- [ ] Control flow: `if`, `for`, `while`, `break`, `continue`, loop `else`
- [ ] `match` statement and structural pattern matching
- [ ] Exceptions: `try` / `except` / `else` / `finally`, raising, custom exceptions, exception chaining
- [ ] File I/O, `pathlib`, context managers (`with`)
- [ ] Modules and imports, `__name__`, packages, relative imports
- [ ] Comprehensions (list, dict, set) and generator expressions
- [ ] Unpacking, `*args` in assignments, the walrus operator

**Deep**
- [ ] How `for` desugars to the iterator protocol
- [ ] Exception handling cost and the EAFP vs LBYL trade-off
- [ ] String interning and immutability consequences
- [ ] Float representation and why `0.1 + 0.2 != 0.3`

**Exercises:** 25 graded problems: text processing, a log parser, a safe file-copy tool, a simple state machine using `match`.
**Deliverable:** A command-line word-frequency analyzer.
**Self-check:** Why does `for ... else` exist, and when does the `else` run?

---

### Module 02: Data Model 🟡

**Goal:** Understand that everything in Python is an object and how to make your own objects feel built-in.
**Prerequisites:** Module 01. **Time:** about 14 h.

**Core**
- [ ] Objects, identity, type and value: `id()`, `is` vs `==`
- [ ] Mutable vs immutable types and aliasing bugs
- [ ] Built-in collections in depth: `list`, `tuple`, `dict`, `set`, `frozenset`
- [ ] `collections`: `deque`, `defaultdict`, `Counter`, `OrderedDict`, `ChainMap`, `namedtuple`
- [ ] Shallow vs deep copy
- [ ] Special methods: `__repr__`, `__str__`, `__eq__`, `__hash__`, `__bool__`, `__len__`, `__getitem__`, `__contains__`, `__iter__`
- [ ] Operator overloading: arithmetic, comparison, in-place, reflected operators
- [ ] `dataclasses` and `functools.total_ordering`

**Deep**
- [ ] The hash/equality contract and what breaks if you violate it
- [ ] How `dict` and `set` work: hash tables, probing, resizing, insertion-order guarantee
- [ ] `list` over-allocation and amortized append
- [ ] Small-int cache and string interning
- [ ] `__slots__`: memory savings and trade-offs
- [ ] Attribute lookup order: instance dict, class, `__getattr__` fallback

**Mastery**
- [ ] Build a `Vector` and `Matrix` class with full operator support
- [ ] Build a `FrozenDict` and a `SortedList` from scratch

**Exercises:** Implement a `Fraction`-like class passing the stdlib test cases; a custom sequence supporting slicing.
**Deliverable:** `src/pydeep/structures/` with three tested data structures.
**Self-check:** Why can't a `list` be a dict key, and what must a custom class do to be one?

---

### Module 03: Functions and Closures 🟡

**Goal:** Treat functions as first-class objects and master scope.
**Prerequisites:** Module 01. **Time:** about 12 h.

**Core**
- [ ] Parameters: positional, keyword, default, `*args`, `**kwargs`, positional-only `/`, keyword-only `*`
- [ ] Return values, multiple returns, `None`
- [ ] Scope: LEGB rule, `global`, `nonlocal`
- [ ] First-class functions, higher-order functions, `lambda`
- [ ] Closures and free variables
- [ ] `functools`: `partial`, `reduce`, `lru_cache`, `cache`, `singledispatch`, `wraps`
- [ ] `operator` module, `itemgetter`, `attrgetter`

**Deep**
- [ ] Mutable default argument trap and why defaults evaluate once
- [ ] Late-binding closures in loops
- [ ] Function objects: `__code__`, `__defaults__`, `__closure__`, `__annotations__`
- [ ] Call stack, recursion limit, tail recursion (and why Python doesn't optimize it)
- [ ] How `lru_cache` is implemented

**Mastery**
- [ ] Write your own `lru_cache` and `partial`

**Exercises:** Closure-based counters and accumulators, a memoization benchmark, a mini dispatch table.
**Deliverable:** `pydeep.decorators.memoize` with a cache-size limit and stats.
**Self-check:** What does `[lambda: i for i in range(3)]` return when called, and why?

### Module 04: OOP and Protocols 🟡

**Goal:** Design clean class hierarchies and know when *not* to use inheritance.
**Prerequisites:** Modules 02, 03. **Time:** about 16 h.

**Core**
- [ ] Classes, instances, `__init__`, class vs instance attributes
- [ ] Methods: instance, `@classmethod`, `@staticmethod`
- [ ] Properties and encapsulation conventions (`_x`, `__x`)
- [ ] Inheritance, `super()`, method overriding
- [ ] Abstract base classes (`abc`)
- [ ] Composition vs inheritance, mixins
- [ ] `dataclasses` in depth: `field`, `frozen`, `slots`, `__post_init__`
- [ ] `enum`: `Enum`, `IntEnum`, `Flag`, `auto`
- [ ] SOLID principles applied to Python

**Deep**
- [ ] Method Resolution Order and C3 linearization
- [ ] Cooperative multiple inheritance with `super()`
- [ ] Bound vs unbound methods, how `self` is passed
- [ ] `typing.Protocol` and structural subtyping vs nominal
- [ ] Duck typing and EAFP in API design

**Mastery**
- [ ] Implement a small plugin framework using ABCs and registration
- [ ] Re-implement a simplified `dataclass` decorator

**Exercises:** Diamond-inheritance puzzles, refactor an inheritance tree into composition, design a shape or payment hierarchy with Protocols.
**Deliverable:** `projects/04-plugin-framework/`.
**Self-check:** Given a diamond hierarchy, can you predict the MRO without running it?

### Module 05: Iterators, Generators, Coroutines 🔴

**Goal:** Lazy evaluation and pipeline thinking.
**Prerequisites:** Modules 02, 03. **Time:** about 16 h.

**Core**
- [ ] Iterable vs iterator, `iter()` and `next()`, `StopIteration`
- [ ] Generator functions and expressions
- [ ] `yield from` and delegation
- [ ] `itertools`: `chain`, `islice`, `groupby`, `tee`, `product`, `accumulate`, `batched`
- [ ] Context managers via `contextlib`: `@contextmanager`, `ExitStack`, `suppress`
- [ ] Generator-based data pipelines for large files

**Deep**
- [ ] Generator frames: suspension, resumption, `gi_frame`
- [ ] `send()`, `throw()`, `close()`, and generator cleanup
- [ ] Generators as coroutines: the road to `async`/`await`
- [ ] Memory profile of eager vs lazy approaches

**Mastery**
- [ ] Build a mini scheduler that runs generator-based coroutines round-robin
- [ ] Implement `itertools.groupby` and `tee` from scratch

**Exercises:** Stream-process a multi-GB file in constant memory; build a pipeline of chained generators.
**Deliverable:** `pydeep.async_utils.scheduler` (generator-based cooperative scheduler).
**Self-check:** Why can you iterate a generator only once, and what does `tee` do about it?

### Module 06: Decorators and Metaprogramming 🔴

**Goal:** Write code that writes or modifies code, without abusing it.
**Prerequisites:** Modules 03, 04, 05. **Time:** about 20 h.

**Core**
- [ ] Function decorators, preserving metadata with `wraps`
- [ ] Decorators with arguments, stacking decorators
- [ ] Class decorators
- [ ] Decorating methods and classes correctly
- [ ] `inspect` module: signatures, source, stack
- [ ] `__getattr__`, `__setattr__`, `__getattribute__`

**Deep**
- [ ] Descriptors: `__get__`, `__set__`, `__delete__`, `__set_name__`
- [ ] Data vs non-data descriptors and attribute lookup precedence
- [ ] How `property`, `classmethod`, `staticmethod` are descriptors
- [ ] `__init_subclass__` and `__class_getitem__`
- [ ] Metaclasses: `type(name, bases, ns)`, `__new__` vs `__init__`, `__prepare__`
- [ ] When metaclasses are the wrong answer

**Mastery**
- [ ] Build a validation framework with descriptors (like a tiny ORM field system)
- [ ] Implement `@dataclass`-like and `@singledispatch`-like decorators
- [ ] Build an auto-registering plugin system via `__init_subclass__`

**Exercises:** `retry`, `timer`, `rate_limit`, `deprecated` decorators; a typed-field descriptor library.
**Deliverable:** `projects/03-mini-orm/`.
**Self-check:** Why does a data descriptor on a class beat an entry in the instance `__dict__`?

### Module 07: Concurrency 🔴

**Goal:** Choose the right concurrency model and avoid its classic bugs.
**Prerequisites:** Modules 04, 05. **Time:** about 24 h.

**Core**
- [ ] Concurrency vs parallelism, CPU-bound vs I/O-bound
- [ ] `threading`: threads, locks, `RLock`, `Event`, `Semaphore`, `Queue`
- [ ] `multiprocessing`: processes, pools, shared memory, pickling constraints
- [ ] `concurrent.futures`: `ThreadPoolExecutor`, `ProcessPoolExecutor`
- [ ] `asyncio`: event loop, tasks, `gather`, `TaskGroup`, timeouts, cancellation
- [ ] `async` iterators, async context managers, `async for`
- [ ] Choosing a model: decision flowchart

**Deep**
- [ ] The GIL: what it protects, what it doesn't, its effect on benchmarks
- [ ] Free-threaded (no-GIL) builds and their implications
- [ ] Race conditions, deadlocks, starvation: reproducing each on purpose
- [ ] How the event loop works: selectors, ready queue, callbacks
- [ ] Back-pressure and bounded queues
- [ ] Structured concurrency and cancellation semantics

**Mastery**
- [ ] Implement a minimal event loop from scratch
- [ ] Build a thread-safe rate limiter and a worker pool
- [ ] Async web scraper with connection limits, retries and graceful shutdown

**Exercises:** The same workload solved with threads, processes and asyncio, with benchmark comparison.
**Deliverable:** `projects/02-async-web-scraper/` plus `benchmarks/bench_gil_threads_vs_procs.py`.
**Self-check:** When does threading speed up a program in CPython, and when does it not?

### Module 08: Memory and Performance 🔴

**Goal:** Measure first, optimize second, understand the machine underneath.
**Prerequisites:** Modules 02, 05. **Time:** about 22 h.

**Core**
- [ ] Profiling: `timeit`, `cProfile`, `pstats`, `line_profiler`, `py-spy`
- [ ] Memory measurement: `sys.getsizeof`, `tracemalloc`, `memory_profiler`
- [ ] Algorithmic complexity in practice with Python's built-ins
- [ ] Choosing data structures for speed: `deque`, `set` lookup, `bisect`, `heapq`
- [ ] Caching strategies
- [ ] Vectorization with NumPy

**Deep**
- [ ] Reference counting and the cyclic garbage collector, `gc` module
- [ ] Weak references and `weakref`
- [ ] Memory fragmentation and the small-object allocator (pymalloc)
- [ ] Why Python is slow: dynamic dispatch, boxing, interpreter overhead
- [ ] The specializing adaptive interpreter and JIT (version dependent)

**Mastery**
- [ ] Optimize one real program 10x, documenting each step with before/after profiles
- [ ] Wrap a hot loop with Cython, Numba or a Rust (PyO3) extension

**Exercises:** Find and fix three planted performance bugs; track down a planted memory leak.
**Deliverable:** `benchmarks/` suite with saved charts and a written optimization case study.
**Self-check:** How can a reference cycle leak memory even with a garbage collector?

### Module 09: CPython Internals ⚫

**Goal:** See what the interpreter actually does.
**Prerequisites:** Modules 02, 03, 05, 08. **Time:** about 26 h.

**Core**
- [ ] The compilation pipeline: source, tokens, AST, bytecode, execution
- [ ] `ast` module: parsing, walking and transforming trees
- [ ] `dis` module: reading bytecode
- [ ] Code objects and frames

**Deep**
- [ ] The evaluation loop and the value stack
- [ ] How function calls, closures and generators look at the bytecode level
- [ ] The import system: finders, loaders, `sys.modules`, import hooks
- [ ] Object layout: `PyObject`, type objects, `ob_refcnt`
- [ ] Reading CPython source on GitHub: where to start and how to navigate
- [ ] Python's C API and writing a minimal C extension

**Mastery**
- [ ] Write an AST transformer (e.g. auto-insert tracing or constant folding)
- [ ] Write a custom import hook
- [ ] Build a tiny bytecode interpreter in Python (stack machine)
- [ ] Contribute a documentation fix or small patch to CPython (stretch)

**Exercises:** Predict bytecode before running `dis`, then compare; explain three surprising behaviors from the bytecode.
**Deliverable:** `projects/05-interpreter-in-python/`.
**Self-check:** What does the interpreter do between reading `x = a + b` and storing the result?

## 7. Quality bar for "Done" (✅)

A topic only moves to ✅ when all of these are true:

- [ ] `notes.md` explains it in plain language first, then precisely
- [ ] At least two runnable, commented examples in `examples/`
- [ ] At least three exercises of graded difficulty with self-verifying tests
- [ ] Solutions merged and passing in CI
- [ ] A "Common mistakes" entry
- [ ] Every Deep-tier claim backed by `dis` output, a source link, or a benchmark
- [ ] Type hints on all code, `ruff` and `mypy` clean
- [ ] Reviewed by at least one other person, or self-reviewed after a one-week gap

## 8. How to use and contribute

**As a learner**
1. Pick a path in section 2.
2. Work through each module in order: notes, examples, exercises, then compare with solutions.
3. Run `make test-module M=<number>` to check your own work.
4. Tick the self-check questions honestly. If you can't answer one, reread the deep-dive.

**As a contributor**
1. Check section 6 or open a `topic-request` issue.
2. Scaffold with `make new-module N=<number> NAME=<slug>`.
3. Follow the quality bar in section 7.
4. Run `make check` before opening a pull request.
